# QQ 音乐登录态续期（纯 Python）

## 范围

QQ 音乐新增尽力而为的自动续期；不需要 Node、独立 API 服务或常驻浏览器，不增加 Python 依赖。扫码二维码、卡片、`CgiGetVkey` 取链、音质回退和发送方式保持不变。酷狗保留现有网页登录与取链作为后备，并新增可选 H5 音质取链；这不是登录续期。

## 使用

- 已有 Cookie 继续使用，不要求为了启用插件而重新扫码。
- 旧 Cookie 文件不包含刷新材料，无法据此自动续期。希望启用续期时，使用管理员指令 `qqlogin` 重新扫码一次；是否具备续期条件仍取决于该次登录响应。
- 只有同一账号的登录响应同时包含 `refresh_key`、音乐凭据和合理的 `musickeyCreateTime` / `keyExpiresIn`，才启用自动刷新。缺字段时仍正常保存播放 Cookie，不虚构有效期。
- 已启用的 QQ 解析器启动后台任务，每小时检查一次。在接口给出的到期时间前六小时内，才发一次最长 15 秒的刷新请求。两次尝试至少间隔一小时，重启后也保留冷却。
- 关闭 QQ 解析器或卸载插件时停止任务。其他平台、卡片渲染和媒体发送不依赖此任务。
- 会话过期超过 30 天不自动尝试恢复；这只是本地有界重试策略，不表示 QQ 承诺支持过期后刷新。

## 保留播放能力

刷新仅接受同账号、同登录类型、含完整必要字段并且有效期明确延长的成功响应。更新现有四个播放 Cookie 的值，保留其他 Cookie 及 domain/path 等属性。

网络错误、平台拒绝、字段缺失、账号不匹配或刷新失败，都不会主动删除现有播放 Cookie。管理员手动改 Cookie、换号、清除 Cookie 或解析器被替换后，旧刷新请求不得覆盖当前账号。续期失败不会切换成网页播放器，也不会用试听替代原来能播放的完整音频。

续期不能保证会员权益、歌曲版权、地区及音质权限，也不能保证永不重新扫码。返回 URL 本身可能短期有效，仍按需取链。

## 酷狗文件音质

在酷狗设置中选择“文件”，再调整“文件音质优先级”：`high`（请求 320 kbps）、`lossless`（请求 FLAC）、`standard`（请求 128 kbps）。默认顺序为 `high → lossless → standard`；想优先无损可把 `lossless` 移到最前。管理页支持增加、移除和排序，语音发送仍使用原取链。

使用网页登录 Cookie 的 `KugooID/t`（也支持复合 `KuGoo`）及 `kg_mid/kg_dfid`。这些是 H5 会话字段，无须转换为 lite 登录。程序保留旧接口返回的标题、歌手、封面和时长；新 H5 URL 下载失败或内容检查未通过时回退原播放。新媒体下载仅允许可信 `webfs.*.kugou.com` HTTPS 地址、禁止重定向、不携带账号 Cookie，并遵守大小、超时及并发限制。其他 CDN 地址将回退旧路径，以后可依据实测扩展。

结果只记录请求音质，不把请求参数当成实际码率验证。显式试听标记会被排除，但缺少标记不构成完整歌曲证明；真实播放与会员权限仍由平台决定。此前单曲验证确认了三个档位返回成功和相应格式，未证明所有曲目的实际编码、时长或发送结果。

## 存储与配置优先级

数据保存在插件原有 cookies 目录：

- `qqmusic_session.enc`：Fernet 加密的刷新材料、稳定请求设备标识和尝试时间。
- `qqmusic_session.key`：本地随机加密密钥。
- `qqmusic_cookies.txt`（以实际解析器名为准）：保留现有格式的播放 Cookie。
- `qqmusic_cookies.import.json`：仅保存配置及 Cookie 文件的 SHA-256 指纹，用于防止未改变的旧配置在重启时覆盖新 Cookie。替换 Cookie 前先记录旧文件和候选新文件的指纹，替换失败或进程中断后可识别实际保留的版本。

已导入的配置未变、且 Cookie 文件匹配上次成功保存的指纹时，优先恢复该文件。配置值发生变化时重新导入配置。旧安装没有导入记录时，仍沿用原先配置优先的规则；不要依赖旧 Cookie 自动补出刷新材料。

刷新状态文件损坏、密钥丢失或无法写入时，播放功能继续工作，续期可能仅在本次进程有效或被跳过。不要手动编辑加密文件。

**安全边界**：本地密钥和密文位于同一个目录，不等同于系统密钥链；能读取整个数据目录的主体仍能解密。播放 Cookie 本身沿用现有明文文件格式。备份需要按敏感凭据保护整个目录，不应上传日志、工单或公开仓库。POSIX 上新增密钥及密文以仅所有者可读写的权限创建；Windows 需由部署者限制数据目录 ACL，不声称自动配置系统级保护。

## 实现依据与验证边界

- Folia 的 `qqSessionRefresh.ts` 提供调度、失败保留与会话轮换的参考。
- 实际音乐凭据刷新协议核对自 Folia 固定的 `@yakult-green-tea/qq-music-api` v3.3.6：`authenticatedReads`、`musicuProtocol`、`androidDevice` 和 `credentialExpiry`。只读研究上游源码，没有运行或部署 Node。
- 使用音乐接口的 `music.login.LoginServer.Login`，`loginMode=2`；携带原登录类型、刷新材料和四个音乐 Cookie。不会保存扫码授权中间步骤的 QQ 全局 `p_skey` 来做后台保活。
- 采用稳定的本地请求标识，不新增 QIMEI 注册或设备引导网络请求。缺少这类上下文是否导致特定账号被拒，需要真实账号验证；被拒时保留原播放 Cookie，而不是改动取链接口。
- **酷狗 H5 音质取链：**Mineradio 使用与当前网页会话兼容的 H5 `/v5/url` 参数协议，可使用 `KuGoo.KugooID/t`、`mid` 和 `dfid`，请求 `quality=320/flac/128`。当前解析器只在文件模式按配置尝试该路径；失败时仍走原有 `songinfo` 和旧接口后备。H5 响应中的 URL 是短期地址，不能替代登录态续期。
- **酷狗续期：**Folia 文档中的 `/login/token` 是第三方封装路由；尚无证据证明该接口可用于当前 Cookie，所以不发送猜测性刷新请求。


离线测试验证 QQ 调度、持久化、并发和失败回退，也覆盖酷狗 H5 签名参数与回退规则。使用更新后的 Mineradio Cookie，对一首会员曲实际请求了 `320`、`flac`、`128`，均返回成功状态与对应音频格式；这是一次定点验证，不证明其他歌曲、账号或长期可用。还需继续验证插件发送、重启、断网、手工换号和禁用解析器。
